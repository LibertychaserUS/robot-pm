# Robot PM 用户手册

Robot PM 是飞书里的项目助理。它按多维表格里的进度帮忙盯事情、记下每个人的职责，并在该开会时发一张卡片。时间用北京时间。

## 怎么说

群里先 @，私聊直接说。

在群里要 @ 它。没有 @ 的群消息，它不处理。

点卡片上的按钮不用再 @。那是飞书自己的回调。

私聊里直接说话即可。

## 进群

进群后说明你的职责。

1. 你进群后，它会 @ 你一次，说明自己是谁。
2. 请再 @ 它，用一句话说明你的职责。
3. 它发一张确认卡片。你点 **确认**，这句职责才写入职责表。点 **取消**，这次不写入。

超过 30 分钟还没点，这次记职责会取消，它会 @ 你说明已经取消。

没写入职责之前，它不拉你开会，也不把待办发给你。

一个人可以有多项职责。同一项职责可以有多个人。职责表还是空的时候，它不发会议卡片，只发记职责的卡片。

## 先确认

点确认才做，点取消就停。

群里的每件事都是两步。它先把计划发给提出人。提出人点 **确认**，它才实施。点 **取消**，这次停掉，表和日历保持原样。

你也可以 @ 它并说「取消」，停掉还在等待的那一件。

计划停在等待，超过 30 分钟，它会 @ 提出人，说明这次已取消。

同时最多 5 个人各进行一件事。已经满了，第 6 个人会收到一张卡片，上面写着现在人满了，请稍后再试。它不会给这个人再建一个进行中的目录。

已经开始实施的那一步不能取消。

## 改进度

说出哪一项，改到哪一步。

你的职责和这件事的职责相同，或者你的职责是 `pm`，才可以让它改进度。

说清楚是哪一项，以及改成哪一种：未开始、进行中、完成、卡住。

它先发确认卡片。你点 **确认**，它才写入。点 **取消**，状态保持原样。

日期按节点处理：

- `deadline` 和 `release` 的日期不能在对话里改。
- `flexible` 的开始或结束可以改，也要点 **确认** 才写入。

标题和前置不能在对话里改。

你点确认的时候，如果这一行已经被人改过，或者这一行已经不在了，这次计划作废，它不会把旧建议写回去。

## 开会

确认后发到群，点同意才订。

它根据表格里的进度和新的事情建议会议。建议里有开始和结束，都是北京时间。

发布节点（`release`）上的会，必须在这个节点的日期之前结束。结束落在节点当天或更晚，这次建议不会发出去。

提出人先点 **确认**，会议卡片才发到群里。群里的按钮是 **同意** 和 **先不办**。

- 点 **同意**，它才在飞书日历上预定，并把职责表里对上这项职责的人加进去。
- 点 **先不办**，它只记下决定，日历上不会有这场会。

没有日历配置时，它不预定。

## 预定会

说清开始和结束，北京时间。

说清楚是哪一项，以及北京时间的开始和结束。它发确认卡片。你点 **确认**，它才预定，并把职责表里对上的人加进去。没点确认，日历上不会有这场会。

## 放文档

放到后台，不要发到群里。

不要把文档发到群里。群里的文件它不导入，也不会在群里发导入进度。

文档放到后台的 `var/robot_pm/inbox/`。它在后台处理，一次一份。

| 文件 | 它怎么处理 |
| --- | --- |
| 合法的清单 JSON | 直接当作清单 |
| Markdown | 抽出标题和正文 |
| Word（`.docx`） | 抽出段落文字 |
| 带文字层的 PDF | 抽出文字 |

扫描版 PDF 没有文字层，它会停下来，不会猜字。其它类型的文件不导入。

## 能问什么

可问进度、职责和开会。

- 问进度：它按表格里的状态回答。
- 问职责：它复述已经记下的职责。还没记下，就请你先去记职责。
- 开会：它先给计划。你确认后，卡片才到群里。

别的话题它不展开。表里没有你的职责时，它不会猜你是谁。
