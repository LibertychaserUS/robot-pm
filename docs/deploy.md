# 部署

这个探针检查一台主机能不能放持久化目录，通过之后才把目录建出来。它不启动 `robot-pm`，不监听端口，也不连接飞书。

`apps/robot-pm/main.cpp` 目前只打印 `robot-pm`。提出人的按钮是 **确认** / **取消**，群里的会议按钮是 **同意** / **先不办**。这些卡片都不是这个探针发的。

## 编译和运行

需要 Python 3.11 或更高，以及一台已经能编译 C 的机器。探针自己还要求 GCC 14 或 Clang 18，以及 CMake 3.28 或更高，因为仓库主体是 C++23。

```bash
python3 -m venv .venv
.venv/bin/pip install -e ".[dev]"
.venv/bin/robot-pm-deploy --data-root var/robot_pm
```

`--data-root` 省略时用环境变量 `ROBOT_PM_DATA_ROOT`，再省略就是当前目录下的 `var/robot_pm`。

成功时打印目录路径和最低字节数。失败时原因写在标准错误上，退出码是 1。环境变量的值不会打印。

`--hold` 会在目录就绪后一直占着写入锁，直到标准输入结束。用来确认第二个进程不能同时准备这棵树。它仍然不启动机器人。

## 它检查什么

按这个顺序。任何一步失败，目录树保持调用前的样子。

1. 这些变量都有非空的值：`FEISHU_APP_ID`、`FEISHU_APP_SECRET`、`FEISHU_ENCRYPT_KEY`、`FEISHU_VERIFICATION_TOKEN`、`FEISHU_BITABLE_APP_TOKEN`、`FEISHU_BITABLE_TABLE_ID`。只检查在不在。
2. 时钟能把现在换算成北京时间（`Asia/Shanghai`，东八区），并且年份落在 2026 到 2100 之间。30 分钟超时和截止日期都靠这个钟。
3. 当前解释器和 `python3` 都是 3.11 或更高，`cmake` 至少 3.28，C++ 编译器是 GCC 14 或 Clang 18。
4. 可用空间。见下一节。数字不够就停，不会先建目录。
5. 按这个字节数真实写一份探针文件并 `fsync`，然后删掉。写失败（包括配额拒绝）就停。这份文件不是目录树。
6. 独占锁 `.writer.lock`。已经有进程占着，就停，不改这棵树。

通过之后才创建这 9 个目录，外加锁文件 `.writer.lock`：

`inbox/`、`handled/`、`working/`、`working/plans/`、`episodic/`、`semantic/`、`semantic/manifests/`、`semantic/supervision/`，以及数据根本身。

一个人进行中的目录 `working/<open_id>/<interaction_id>/` 要等真正有交互时才建。探针只保证到时候有地方、有空间。

数据根目录收成只有当前用户可读写。第二个人不能靠权限去共用这棵树；第二个进程也不能靠再跑一次探针去共用，锁被占着就会失败。

## 最低空间

**135168 字节**（33 × 4096）。低于这个数就拒绝。

4096 是 ext4 上一份小文件或一个目录至少占的块。逻辑内容比一块小，所以按块记账，不按「看起来只有几十字节」。

同时最多 5 个人。一个人一份交互、一份收件、结束时一条墓碑。命令是串行的，但 5 份会同时留在盘上：结束时先写墓碑，再删交互目录。

| 内容 | 逻辑字节 | 占多少块 |
| --- | --- | --- |
| 一份交互 `context.json` | 186 | 1 |
| 一份收件清单 | 301 | 1 |
| 一个人的两级目录 |  | 2 |
| 5 个人 |  | 20 |
| 5 条墓碑合成 `events.jsonl` | 5 × 165 | 1 |
| 5 条到期审计合成 `audit.jsonl` | 5 × 204 | 1 |
| 追加时的一个 `.tmp` | 和上面较大的那份一样 | 1 |
| 骨架 9 个目录加锁文件 |  | 10 |
| 合计 |  | 33 × 4096 = 135168 |

交互文件是一条状态计划：工作项、看见的状态和日期、要改成的状态、`created_unix`。收件是导入路径接受的一份工作项清单（一份文档、一节、一条工作项）。墓碑五个字段是 `interaction_id`、`actor`、`op`、`outcome`、`time`。标识按飞书 `ou_` / `om_` 加 32 位十六进制的宽度来量。审计是 30 分钟到期时、删目录之前多写的那一行，算在余量里。

空闲字节用 `statvfs` 的 `f_bavail`（这个进程真正还能写的），不用 `f_bfree`。`f_bfree` 含保留块，只看它会把一台其实写不进去的主机当成没问题。

文件系统如果通过配额系统调用报告了用户、组或项目配额，剩余空间取空闲字节和配额剩余里更小的那个。配额块是 1024 字节；当前用量按字节。限额是 0 表示这项不封顶。空闲看起来够、配额不够，一样失败。inode 表或 inode 配额不够，也失败。

文件系统的块比 4096 大时，按实际块重算，只升不降。目录已经存在时，已经占掉的骨架不再重复计算，仍然要求剩下的空间够 5 个人的交互、收件和墓碑。

持续集成没有飞书凭证时会跳过真正的准备，不会因为缺密钥把构建打红。探针测试用的是占位符。
